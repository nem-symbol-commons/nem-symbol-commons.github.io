ビルド済みの NEM(NIS1)ノードを Ubuntu 26.04 LTS（amd64）にインストールします。

NIS v0.6.102 を対象とします。現在の要件は [ノード構築ガイド](https://docs.nemtest.net/en/userbook/node/install/) と [リリース](https://github.com/NemProject/nem/releases/tag/v0.6.102) を確認してください。
`nem.folder` の保存先とサービス実行ユーザーの書き込み権限を合わせ、`nis.bootKey` を含む設定ファイルは公開しないでください。

## 必要パッケージと作業ユーザー

以下は sudo を利用できる、root 以外の Linux ユーザーで操作します。このユーザーで設定を編集・手動起動し、サービスの実行ユーザーにも同じユーザーを指定します。

```sh
sudo apt update
sudo apt install openjdk-11-jre-headless curl jq
whoami
id -gn
```

Java は Ubuntu の [OpenJDK 11](https://packages.ubuntu.com/resolute/openjdk-11-jdk)（universe）を使います。ほかの Java が入っていても、このシェルでは Java 11 を選びます。

```bash
export JAVA_HOME=/usr/lib/jvm/java-11-openjdk-amd64
export PATH="$JAVA_HOME/bin:$PATH"
java -version
```

表示が `11` 系であることを確認してください。別のシェルで手動起動する場合も、この指定を行います。

## NEM(NIS1)クライアントのダウンロード

NIS1 クライアントの最新版は、下記のリンクから確認できます。

[https://github.com/NemProject/nem/releases](https://github.com/NemProject/nem/releases)

2025 年 10 月 1 日時点の最新バージョンは `v0.6.102` です。

```sh
curl -OL https://github.com/NemProject/nem/releases/download/v0.6.102/nis-0.6.102.tgz
```

展開します。

```bash
tar -xzvf nis-0.6.102.tgz
rm nis-0.6.102.tgz
```

展開された `package` ディレクトリは、任意の場所に配置してください。

## NIS1 の設定

### 配置場所

ここでは`/opt`に配置する例を紹介します。

```bash
sudo mv package /opt/nis1
sudo chown -R "$(id -un):$(id -gn)" /opt/nis1
cd /opt/nis1
```

この例では `nem.folder = /opt/nis1` とし、DB はその配下の `nis/data/`、ログは `nis/logs/` に作成されます。[DB 設定](https://github.com/NemProject/nem/blob/v0.6.102/nis/src/main/resources/db.properties)・[ログ設定](https://github.com/NemProject/nem/blob/v0.6.102/nis/src/main/resources/logalpha.properties)を参照してください。
保存先やサービス実行ユーザーを変える場合も、実行ユーザーが保存先へ書き込める所有権・権限にそろえます。

### 委任秘密鍵を確認する

NEM NanoWallet で、設定に使う委任用アカウントの秘密鍵を確認します。

1. 対象のネットワークのウォレットにログインします。
2. `Services` → `Delegated Harvesting` → `Manage delegated account` を開きます。
3. `Show delegated account keys` を選び、ウォレットのパスワードを入力して委任秘密鍵を表示します。

表示された委任秘密鍵を、以下の `YOUR_DELEGATED_PRIVATE_KEY` に設定します。**資産を持つ主アカウントの秘密鍵は使わないでください。**
画面の項目名は英語表示で記載しています。[公式の委任秘密鍵の確認手順](https://docs.nemtest.net/en/userbook/node/supernode-program/)も参照してください。

### コンフィグファイルの作成と編集(メインネット)

`config-user.properties`ファイルを新規作成し、必要な項目を設定します。

```bash
umask 077
touch nis/config-user.properties
chmod 600 nis/config-user.properties
vi nis/config-user.properties
```

秘密鍵を保存するため、このファイルは実行ユーザーだけが読み書きできる `600` に制限します。Testnet でも同じファイルと権限を使います。

- `nem.folder`: ブロックデータの保存先（デフォルトは `~/nem`）
- `nem.host`: ドメインがない場合は IP アドレスを指定します
- `nis.bootName`: ノードの名前
- `nis.unlockedLimit`: ハーベストを受け入れる人数の上限（デフォルトは 4、10 程度が一般的です）
- `nis.ipDetectionMode`: ドメイン設定時に IP アドレスになるのを防止
- `nis.bootKey`: 起動用の専用秘密鍵。委任ハーベストを使う場合は委任用アカウントの秘密鍵を指定し、資産を持つ主アカウントの秘密鍵は設定しない

以下の Mainnet・Testnet の設定例では、プレースホルダーを実際の値に置き換えます。

| プレースホルダー             | 設定する値                           |
| ---------------------------- | ------------------------------------ |
| `YOUR_NODE_DOMAIN_OR_IP`     | ノードのドメイン名または IP アドレス |
| `YOUR_NODE_NAME`             | ノードの名前                         |
| `YOUR_DELEGATED_PRIVATE_KEY` | 委任用アカウントの秘密鍵             |

```ini title="nis/config-user.properties"
# ブロックデータ保存ディレクトリ
nem.folder = /opt/nis1

# ホスト名
nem.host = YOUR_NODE_DOMAIN_OR_IP

# ブート名(ノードの名前です)
nis.bootName = YOUR_NODE_NAME

# ハーベストを受け入れる人数の上限値
nis.unlockedLimit = 10

# HOSTがIPにならないようにする
nis.ipDetectionMode = Disabled

# 委任秘密鍵
nis.bootKey = YOUR_DELEGATED_PRIVATE_KEY
```

### コンフィグファイルの作成と編集(テストネット) {/* #testnet-config */}

テストネットの場合は、追加で設定が必要です。

```ini title="nis/config-user.properties"
nem.network = testnet
nis.treasuryReissuanceForkHeight = 1
nis.treasuryReissuanceForkTransactionHashes =
nis.treasuryReissuanceForkFallbackTransactionHashes =
nis.multisigMOfNForkHeight = 1
nis.mosaicsForkHeight = 1
nis.firstFeeForkHeight = 1
nis.secondFeeForkHeight = 1
nis.remoteAccountForkHeight = 1
nis.mosaicRedefinitionForkHeight = 1

# ブロックデータ保存ディレクトリ
nem.folder = /opt/nis1

# ホスト名
nem.host = YOUR_NODE_DOMAIN_OR_IP

# ブート名(ノードの名前です)
nis.bootName = YOUR_NODE_NAME

# ハーベストを受け入れる人数の上限値
nis.unlockedLimit = 10

# HOSTがIPにならないようにする
nis.ipDetectionMode = Disabled

# 委任秘密鍵
nis.bootKey = YOUR_DELEGATED_PRIVATE_KEY
```

## NIS1 ノードの起動確認

一度ノードを起動し、動作を確認します。

### 起動

```bash
sh nix.runNis.sh
```

### ポート開放

7890 はノード通信、7778 は WebSocket を外部提供する場合の例です。WebSocket を提供しない構成では 7778 の開放は不要です。

```bash
sudo ufw allow 7890/tcp
sudo ufw allow 7778/tcp
```

### 起動とネットワークを確認する

ノードの状態を確認します。

```bash
curl -s http://127.0.0.1:7890/heartbeat | jq
```

正常時は `code: 1`・`message: "ok"` が返ります。[heartbeat の仕様](https://nemproject.github.io/#heart-beat-request)を参照してください。これはプロセスの起動確認で、同期完了を示すものではありません。

ノードの基本情報を確認します。

```bash
curl -s http://127.0.0.1:7890/node/info | jq
```

`identity.name`・`endpoint.host` が設定したノード名・ホスト名と一致することを確認します。`metaData.networkId` は Mainnet が `104`、Testnet が `-104`（`0x98` の符号付き表記）です。[ネットワーク識別子の実装](https://github.com/NemProject/nem/blob/v0.6.102/core/src/main/java/org/nem/core/model/NetworkInfos.java)と照合し、Testnet では[フォーク設定](#testnet-config)も確認してください。
チェーン読込み中に `NIS_ILLEGAL_STATE_LOADING_CHAIN` が返る場合は、ログを確認しながら読込みを待ちます。

### 同期状況を確認する {/* #synchronization */}

ブロック高を確認します。

```bash
curl -s http://127.0.0.1:7890/chain/height | jq
```

応答の `height` を、**同じネットワーク**の[ノードリスト](#ノードリスト)にある他ノードの高さと比較します。時間を置いて繰り返し、高さが増えて追いつくことを確認してください。差が縮んでいる間は同期中です。
初回同期には時間がかかります。同期完了後にハーベスティングやスーパーノード登録へ進みます。[公式の同期・監視手順](https://docs.nemtest.net/en/userbook/node/install/#synchronization)も参照してください。

### 停止

```bash
curl -s http://127.0.0.1:7890/shutdown
```

## サービス化(デーモン化)

`YOUR_SERVICE_USER`・`YOUR_SERVICE_GROUP` は、冒頭の `whoami`・`id -gn` で確認した作業ユーザー名・グループ名に置き換えます。設定ファイルの所有者とサービス実行ユーザーをそろえてください。

```bash
sudo vi /etc/systemd/system/nis1.service
```

```ini title="/etc/systemd/system/nis1.service"
[Unit]
Description=NIS1 Client
After=network.target

[Service]
ExecStart=/usr/lib/jvm/java-11-openjdk-amd64/bin/java -Xms4G -Xmx8G -XX:+UseG1GC -cp ".:./*:../libs/*" org.nem.deploy.CommonStarter
ExecStop=/usr/bin/curl -s http://127.0.0.1:7890/shutdown
Restart=on-failure
RestartSec=2
User=YOUR_SERVICE_USER
Group=YOUR_SERVICE_GROUP
StandardOutput=journal
StandardError=journal
WorkingDirectory=/opt/nis1/nis
SuccessExitStatus=143
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

`-Xms4G` は初期ヒープ、`-Xmx8G` は最大ヒープの例です。OS、ヒープ以外の Java メモリ、Servant など同居サービスの使用量を残せる値に変更してください。起動後のメモリ使用量とログを確認して調整します。
サービスはシェルの `JAVA_HOME`・`PATH` に依存せず、Java 11 の実行ファイルを直接指定しています。

### サービスをリロード

ユニットファイルを編集した後、systemd に変更をリロードする必要があります。

```bash
sudo systemctl daemon-reload
```

### サービスを有効化

サービスを有効化して、システム起動時に自動的に起動するように設定します。

```bash
sudo systemctl enable nis1
```

### サービスを開始

サービスを開始します。

```bash
sudo systemctl start nis1
```

### サービスを停止

サービスを停止します。

```bash
sudo systemctl stop nis1
```

### ログの確認

nis1 サービスのログを確認します。最新から見るには `-r` オプションを使います。

```bash
sudo journalctl -u nis1 -r
```

リアルタイムで確認したい場合は `-f` オプションを使います。

```bash
sudo journalctl -u nis1 -f
```

時刻などの付加情報を省き、メッセージ本文だけを表示する場合は、[`-o cat`](https://www.freedesktop.org/software/systemd/man/latest/journalctl.html#cat) を指定します。

```bash
sudo journalctl -u nis1 -f -o cat
```
