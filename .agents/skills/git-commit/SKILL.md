# Git Commit

## 目的

コミットの内容と意図が追跡できるように、Git の変更を論理的な単位で整理する。
このリポジトリでは **type（英語）+ 説明（日本語）** を基本とする。

## 作業前の確認

1. `git status --short --branch` で現在のブランチと変更を確認する。
2. `git diff`、`git diff --staged`、未追跡ファイルを確認する。
3. 他者の変更、関連しない変更、生成物が混入していないか確認する。
4. 変更の目的が複数ある場合は、コミットを分割する。
5. 秘密鍵、ニーモニック、API トークン、認証情報、個人情報、`.env` などが含まれていないか確認する。秘密情報の値自体は出力しない。

## コミットメッセージ

形式：

```text
<type>(<scope>): <日本語の要約>
```

`scope` は任意。件名は具体的かつ簡潔にする。

| type | 用途 |
| --- | --- |
| `docs` | 技術記事の追加・更新、説明文・図の修正 |
| `fix` | 不具合修正 |
| `feat` | サイトやアプリケーションの機能追加 |
| `ci` | GitHub Actions などの CI/CD 変更 |
| `chore` | 依存関係更新・保守作業 |
| `refactor` | 振る舞いを変えない構造変更 |
| `test` | テストの追加・修正 |

ドキュメントの新規記事は原則 `docs` を使い、記事を追加しただけで `feat` にしない。

```text
docs(symbol): ノード構築ガイドを追加
docs: NEMとSymbolの違いを整理
fix: サイドバーのリンク切れを修正
ci: GitHub Pagesのデプロイ手順を修正
chore: Docusaurusの依存関係を更新
```

コミット本文は、変更理由や互換性への影響を説明する必要がある場合に追加する。

## コミット作成の手順

1. 対象ファイルを明示して `git add <path>...` でステージする。無条件の `git add .` は避ける。
2. `git diff --cached --check` と `git diff --cached` でステージされた変更を再確認する。
3. 内容に応じて検証する。
   - Docusaurus の記事・設定を変更した場合：`pnpm build`
   - TypeScript を変更した場合：必要に応じて `pnpm typecheck`
   - 検証不能なら、未実行の理由を明記する。
4. **ユーザーがコミット作成を明示的に依頼した場合に限り** `git commit -m "..."` を実行する。
5. 実行後、コミット SHA・メッセージ・対象ファイル・検証結果を報告する。

## 禁止・注意事項

- 明示的な依頼なく `git push`、`git rebase`、`git reset --hard`、`git commit --amend`、強制 push を行わない。
- 既存のステージ済み変更を勝手に外さず、ユーザーの未コミット変更を上書きしない。
- Git のユーザー名・メールアドレスを勝手に変更しない。
- `--no-verify` などでチェックを回避しない。
- ビルド未実行または失敗時に「検証済み」と報告しない。
- ファイル作成や修正のみの依頼を、コミット・push の許可と解釈しない。

## 出力

コミットを作成した場合は `<短いSHA> <メッセージ>` と検証結果を簡潔に示す。
メッセージ案のみの依頼なら、候補と選定理由を示して終了する。
