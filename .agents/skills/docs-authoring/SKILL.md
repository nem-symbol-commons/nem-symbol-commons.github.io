# Documentation Authoring

## 目的

技術的に正確で、保守しやすい日本語の
開発者向けドキュメントを作成する。

## 作業手順

1. 既存ドキュメントとディレクトリ構造を確認する。
2. 対象機能の仕様と実装を調査する。
3. 一次情報を優先して事実関係を検証する。
4. Markdown / MDX で記事を作成する。
5. 必要に応じてコード例や設定例を追加する。
6. ナビゲーションとの整合性を確認する。
7. pnpm build でビルドを検証する。

## 執筆ルール

- 初学者にも理解できる説明を心がける。
- 専門用語を過度に言い換えない。
- 技術的な詳細を省略しすぎない。
- 実行可能なコード例を優先する。
- コード例には対象バージョンを明示する。
- 未検証のコマンドを動作確認済みと表現しない。
- NEM と Symbol の仕様差異を明確にする。

## 完了条件

- 技術的な説明に根拠がある。
- 既存記事との重複が適切に整理されている。
- ドキュメント内の参照先が正しい。
- Docusaurus のビルドが成功している。
